# PicoAgent配布を公開する

## 公開条件を固定する

1. 本体リポジトリの公開用PRが`main`へsquash merge済みであることを確認する。
2. 本体`distribution/site/`とこのリポジトリの公開ファイルを比較する。
3. 同じ版のReleaseが既にあれば上書きせず停止する。通常更新はpatchを上げる。minor／majorはユーザー指示なしに上げない。
4. ベータ期間はLP、README、Release名へ完全な版番号と`Beta`を表示する。
5. 画像差し替えの指示がなければ画像を編集せず、公開前後のハッシュ一致を確認する。

## 配布ファイルを照合する

1. 本体の正規ビルド入口で生成したインストーラだけを使う。
2. ファイル名、PEまたはアプリバンドル形式、生成時刻、バイト数、SHA-256を取得する。
3. `latest.json`の版、Release URL、資産URL、バイト数、SHA-256を実ファイルへ一致させる。
4. 空のプラットフォーム欄を埋めたふりをしない。未公開は空のままにする。

## LPを確認する

1. 全取得ボタンを今回の版のReleaseへ向ける。
2. PC幅と390px前後のスマートフォン幅で実ブラウザー表示する。
3. 横はみ出し、画像欠落、キャラの見切れ、固定バーの重なり、古い版・古い機能説明を確認する。
4. 画像の読み込み成功をDOMでも確認する。遅延読み込み画像を未読込だけで欠落扱いしない。

## PRとReleaseを公開する

1. `origin/main`から公開専用ブランチを作る。
2. 変更をコミットし、push、PR作成、squash mergeまで行う。
3. マージ後の`main`から新しいプレリリースを作り、対応するインストーラを添付する。
4. Release資産のAPI上のサイズとdigestを確認する。
5. 別の一時フォルダへ資産を再ダウンロードし、元ファイルとサイズ・SHA-256が一致することを確認する。

## Pagesを検証する

1. Pagesの最新ビルドが配布リポジトリのマージコミットを指して`built`になるまで待つ。
2. 公開URLの`latest.json`を取得し、版、URL、サイズ、SHA-256を照合する。
3. 公開LPをPC幅とスマートフォン幅で再確認する。
4. 本体`distribution/site/`と公開リポジトリのサイトファイルを比較する。運用用`AGENTS.md`、`.agents/`、`.claude/`は比較対象外にする。

## 掃除して完了する

1. ローカルHTTPサーバー、ブラウザー検証タブ、ビルド補助プロセスを終了する。
2. 検証用ダウンロード、ログ、一時クローン、旧インストーラを削除またはごみ箱へ移す。
3. `.part`、`.incoming`、導入途中フォルダ、旧版インストーラが残っていないことを確認する。
4. PR、Release、Pages、資産サイズ、SHA-256、検証結果、画像変更の有無、掃除結果を報告する。

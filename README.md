# PicoAgent

**ローカル推論・ツール実行・音声・キャラクター表示を統合した、Rust / Tauri製のデスクトップAIエージェント。**

自然言語の依頼をモデルの応答とツール実行のループへ接続し、PC上の作業まで扱うアプリです。LLMの接続先を差し替える共通インターフェース、複数AIの協調、ローカル推論エンジンの管理、操作権限とデータ保護、常駐UIを一つの製品へ組み込んでいます。

| 領域 | 実装・設計 |

## アーキテクチャ

```mermaid
flowchart TB
  INPUT["テキスト・音声・ファイル入力"] --> APP["Tauri / Rust"]
  APP --> AGENT["エージェントループ"]
  CONTEXT["人格・会話履歴・長期メモリ"] --> AGENT
  AGENT <--> PROVIDER["Provider / 共通メッセージ形式"]
  PROVIDER <--> LOCAL["llama.cpp / Ollama"]
  PROVIDER <--> REMOTE["クラウドAPI / CLIエージェント"]
  AGENT --> POLICY["操作権限・入力検査"]
  POLICY --> TOOL["Tool / JSON Schema"]
  TOOL --> RESULT["ファイル・PC操作・外部サービス"]
  TOOL <--> MCP["外部MCPサーバー"]
  TOOL --> AGENT
  AGENT --> CHECK["回答の公開前検査"]
  CHECK --> UI["会話画面・字幕・履歴"]
  CHECK --> VOICE["AivisSpeech / 読み上げ"]
  VOICE --> CHARACTER["PIXI.js / Live2D / 口パク"]
```

### 1. モデルと実行能力を分離する

エージェントループは、プロバイダ固有のAPI形式を直接扱いません。会話・ツール呼び出し・実行結果を共通メッセージへ正規化し、各`Provider`が接続先の形式へ変換します。OpenAI互換API、Claude、Geminiなどで異なる応答形式を、この境界で吸収します。

実行能力は別の`Tool`インターフェースが持ちます。名前・説明・引数のJSON Schema・実行処理を登録し、設定項目は`config_schema()`で宣言します。接続先の追加とツールの追加を分離し、モデルを変更してもアプリ側の操作権限を共通に保つ設計です。

CLIエージェントはネイティブのfunction callingと同じ扱いにはできないため、応答JSONをツール呼び出しへ変換します。CLI側の実行能力を制限し、ファイルやPC操作はPicoAgentのツール境界を通します。この経路は通常のAPI接続よりツール呼び出しの取りこぼしがありえます。

### 2. ツール実行を制御可能なループにする

基本の流れは「モデル呼び出し → ツール呼び出し → 結果を会話へ追加 → モデル呼び出し」です。複数のツール呼び出しは並行実行し、ステップ上限と中断処理で実行を制御します。プロバイダの一時的な失敗は指数バックオフ付きで再試行し、認証・パラメータ不正は再試行せず返します。

複雑な依頼には計画生成と自己評価を組み合わせ、複数AIでは同じ依頼への合議、担当別の分担、まとめ役による統合を扱います。同梱ローカルAI同士は直列化し、それ以外は並行数に上限を設けます。協調実行は単一モデルより応答時間とAPI利用量が増えるため、用途に応じて選ぶ機能です。

### 3. ローカルAIをアプリの実行基盤として管理する

llama.cppを独立した推論プロセスとして起動し、アプリが起動確認と終了処理を管理します。GGUFモデルを使い、初回取得後のローカル会話はPC内で処理できます。Web検索や外部サービス、クラウドモデルを選んだ場合は通信が発生します。

開発版のWindowsではGPUに応じてCUDA／ROCm／SYCL、Vulkan、CPUの候補を起動確認します。候補の存在だけで利用可能と扱わず、対象環境と実際の起動結果を確認する設計です。大容量の追加モデル・ランタイムは明示的に選んだ機能だけを導入し、通常の開発起動や軽量ビルドへ一括取得を混ぜません。

取得資産はSHA-256で照合し、管理情報と実体を対応付けます。設定・会話履歴・追加キャラ・モデルを保持する更新経路を設け、子プロセスや取得途中のファイルも管理対象にしています。

### 4. AIの出力と利用者データの境界を守る

- **操作権限**: ファイル操作の許可ルートを限定し、削除相当はOSのゴミ箱へ移します。PC操作・ブラウザ操作・ローカルAPI・MCPは既定で無効です。
- **外部入力**: ツール結果や添付本文を非信頼入力として扱い、プロンプトインジェクションの検査を行います。この検査だけで攻撃を完全に防げるとは扱いません。
- **公開する回答**: モデルの生チャンクをそのまま画面へ出さず、内部資料や非公開文脈の混入を検査した本文を画面・音声・履歴で共有します。即時表示より公開前検査を優先する設計です。
- **状態の整合性**: 一覧の「読み込み → 更新 → 保存」を状態ごとのロックで直列化します。破損した保存データは退避し、設定内の一覧を読めない場合は空一覧で上書きせずエラーにします。多重起動も防ぎます。
- **秘密値とAPI**: WindowsのAPIキー等はDPAPIで保護します。ローカルHTTP APIは`127.0.0.1`へ限定し、Bearer認証に対応します。開発版ではOriginとJSON Content-Typeも検査します。

### 5. 生成工程と常駐描画を分離する

付属7体の2D／2.5Dキャラクターは、LocalVTuberStudioで立ち絵を部位分解・局所補完した素材を使います。制作側のPython・PyTorchと、実行側のRust・JavaScriptを分離し、表示中は画像生成モデルを動かしません。

```text
立ち絵 → 背景分離 → DINO / SAMによる部位分解 → 2.5Dリグ化
       → Qwen / ComfyUIによる局所補完
       → character.json + PNGパーツ
       → 共通PIXI描画 → まばたき・母音口パク・視線・表情
```

各工程の成果物を保存し、失敗した工程以降だけを再実行できます。原画は上書きせず、未完成の素材を正常な素材として表示しません。任意の入力画像で同じ品質になる保証はまだありません。Live2Dは利用者が権利を持つCubism 4／5モデルの読み込みに対応し、モデル素材は配布物に同梱しません。

## 検証と現在の境界

本体の`cargo xtask verify`に、書式・全targetの静的解析・テスト・JavaScript構文・画面の契約テスト・Git差分検査をまとめています。設定キーと文書の対応、状態更新のロック、破損時の退避、回答の公開前検査など、設計上守るべき制約も機械検査の対象です。依存変更時は`cargo audit`で既知脆弱性を確認します。

静的検査やロジックテストだけでは、Windows WebView2での表示、マイク入力、音声の聴感、GPU推論、クリーン環境へのインストールは保証できません。これらは実機受入として分けて確認します。現時点ではアルファ版であり、全環境での動作・素材品質・正式配布の署名は受入を進める対象です。性能の数値は、このREADMEでは未計測の値を掲載しません。

- テキスト／音声会話、読み上げ、口パク、まばたき、視線、表情、ふれあい、長期記憶
- 7つの表示形式（ペット／マスコット／LINE風チャット／バー／作業／配信／ウィジェット）、OBS風の直接配置、キャラやフキダシの位置・大きさ・背景保存

### AIモデル

| 接続先 | 内容 |
|---|---|
| 同梱ローカルAI（既定） | 推論エンジンを同梱。初回だけモデルを取得し、以後はオフラインでも会話できます |
| Ollama | 既に導入済みのOllamaへ接続できます |
| 手元のCLIエージェント | Claude CodeやCodex CLIをそのまま接続先に指定できます。導入とログインは利用者が行います |
| クラウドAI（任意） | OpenAI、Anthropic（Claude）、Google Gemini、DeepSeek、xAI、Mistral、OpenAI互換API。各社の利用料が発生します |

APIキー等はWindowsのDPAPIで暗号化して保存し、同じWindowsユーザーだけが復号できます。

### 開発者向け（既定は無効）

- ローカルHTTP API: 127.0.0.1のみ・Bearer認証対応。Ollama風の`/api/chat`とOpenAI互換の`/v1/chat/completions`に対応します。
- MCPサーバー: `/mcp`でPicoAgentのスキルをMCPツールとして公開できます。
- MCPクライアント: 外部のMCPサーバーを登録すると、そのツールがスキル一覧へ加わります。

## インストール

1. [Releases](https://github.com/benybeny777/PicoAgent-Distribution/releases)から最新の`PicoAgent_*_x64-setup.exe`をダウンロードします。
2. インストーラを実行します。SmartScreenが表示された場合は、発行元と取得元がこのリポジトリであることを確認してから進めます。
3. PicoAgentを起動し、初回画面で用途と必要な追加機能を選びます。
4. ローカルAIを使う場合は、初回だけモデル取得のためインターネット接続と数GBの空き容量が必要です。

Windows 10／11（64bit）はv1.1.5、macOS Apple Siliconは現行v1.0.4のアルファ版を公開しています。macOS版は未署名のため、正式配布前に署名・公証を追加します。

## 簡単な使い方

- キャラクターまたはフキダシをクリックして会話を開き、文字を入力します。
- キャラクターをドラッグするとウィンドウを移動できます。
- 右クリックの「設定…」でキャラ、表示形式、位置・大きさ、音声、AIモデルを変更できます。
- ファイル操作や外部連携は、設定で許可した範囲だけを使います。
- 問題が起きた場合は[Issues](https://github.com/benybeny777/PicoAgent-Distribution/issues)へ、PicoAgentのバージョンと再現手順を添えて報告してください。APIキー、会話全文、個人ファイルは掲載しないでください。

## よくある質問

- **オフラインでも使えますか**: 初回にモデルを取得したあとは、ローカルAIとの会話をオフラインで続けられます。通信が必要なスキルだけが使えません。
- **データはどこに保存されますか**: 設定、会話履歴、長期記憶、関係性、実行履歴、追加キャラ、取得したモデルはすべてPC内に保存されます。
- **勝手にファイルを消しませんか**: 消しません。許可したフォルダの中だけを扱い、削除相当は必ずゴミ箱へ移します。物理削除コマンドはコマンド実行や予約実行の経路でも拒否します。
- **Live2Dモデルは付属しますか**: 付属も自動取得もしません。動作例は条件を確認したうえで表示している公式サンプルです。初回案内の「公式サンプルを見る」等から利用条件を確認して1体分のzip／フォルダを取得し、「Live2Dを追加する」で選んでください。後回しにしても付属2Dキャラで起動でき、「使い方」→「初回セットアップをもう一度開く」または「キャラ・音声」から追加できます。
- **アンインストールは**: Windowsの「アプリと機能」から削除できます。設定や会話履歴を残すか消すかを選べます。

最新版情報は`latest.json`、詳細な案内は[配布ページ](https://benybeny777.github.io/PicoAgent-Distribution/)を参照してください。
## この公開リポジトリについて

公開サイトの正本はこのリポジトリの`main`です。GitHub Pagesのワークフローが静的ファイルを配信します。アプリ本体のソースコードはこのリポジトリに含みません。公開READMEの技術概要と動作プレビュー、Releasesの配布物から、設計と実際のアプリを確認できます。
